# 📜 Регламент разработки (React/TS Git Workflow)

Данный документ устанавливает обязательные правила работы с репозиторием. Соблюдение регламента гарантирует чистоту кода и упрощает Code Review.

---

## 🚀 1. Правила версионирования (SemVer)
Мы используем семантический подход для контроля релизов:
* **Major** (`1.0.0`): Глобальные изменения, рефакторинг архитектуры или ломающие API изменения.
* **Minor** (`+0.1.0`): Новая фича, страница или компонент (например, `v0.2.0` -> `v0.3.0`).
* **Patch** (`+0.0.1`): Исправление багов, опечаток, стилей или обновление зависимостей (`v0.2.0` -> `v0.2.1`).

---

## 📝 2. Формат коммитов
Запрещены пустые или неинформативные сообщения (типа "fix", "update"). 
Рекомендуется придерживаться стиля **Conventional Commits**.

**Шаблон:**
`[Раздел/Тип] / [Название] / [Версия]`

**Примеры заголовков:**
- `feat(auth): User-Registration / v0.5.0`
- `fix(ui): Button-Jump-Issue / v0.5.1`
- `refactor(api): Axios-Instance-Cleanup / v0.6.0`

**Пример подробного коммита:**
> feat(forms): Contact-Form / v0.7.0
>
> Добавлена форма обратной связи. 
> Настроена валидация через React Hook Form + Zod.
> Добавлены маски для ввода номера телефона.
